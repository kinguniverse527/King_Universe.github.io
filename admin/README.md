# 写作室

这是博客自带的可视化文章编辑器。可以离线写作，也可以连接 GitHub，读取、更新、发布和删除博客文章。日常使用已打包好的文件，不需要安装 Node 或运行构建命令。

## 打开与写作

1. 完整解压博客项目，用浏览器打开 `admin/index.html`，保留旁边的 `modules`、`vendor` 和样式文件。
2. 点击草稿栏的 **＋** 新建文章，填写标题、日期、摘要；网址短名可以留空，由标题生成。
3. 使用工具栏设置小标题、加粗、列表、引用、链接和代码块，右侧可以切换桌面与手机预览。
4. 修改后会自动保存到当前浏览器的 **IndexedDB**，也可点击“保存草稿”或按 `Ctrl+S`。关闭前确认底部显示“已保存到本机”。

草稿连同图片只保存在当前浏览器中。换浏览器、清理浏览数据、从本地文件切换到网上地址，都可能使用不同的草稿库；重要文章请导出备份。若浏览器禁止本地存储，页面会提示失败，此时先导出文章。

博客发布后也可以从 `https://kinguniverse527.github.io/admin/` 打开同一写作室；该地址需先把项目更新到 GitHub 并完成部署。

## 首次连接 GitHub

1. 点击 **连接 GitHub**。默认用户名为 `kinguniverse527`，仓库为 `kinguniverse527.github.io`，分支为 `main`。
2. 点击窗口中的 **GitHub 授权码设置**，登录自己的 GitHub 账号。
3. 创建 **Fine-grained personal access token**：Repository access 选择 **Only select repositories**，只选博客仓库；Repository permissions 中把 **Contents** 设置为 **Read and write**，选择有效期并生成。
4. 将授权码粘贴回写作室。在自己的电脑上，可勾选 **记住此浏览器，30 天内自动连接**，然后点击 **连接仓库**。以后打开写作室会自动验证并恢复连接。

这里使用仓库专用授权码，不是 OAuth 跳转登录。不勾选记忆时，授权码只保留在本页内存中。勾选后会把授权码和对应仓库保存到此浏览器的 localStorage，最长保留 30 天；同站点脚本能够访问此存储，因此只应在自己的设备上开启。输入框会清空，授权码不会写入草稿、导出备份或项目文件。点击 **账号设置 → 退出并忘记连接** 会清除保存的授权并断开其他打开的写作窗口，但不会删除草稿。GitHub 授权提前过期或被撤销时仍需重新连接；临时网络故障不会清除记忆。不要把授权码发到聊天或提交到仓库。

## 查找全部文章

打开后，左侧 **全部文章** 自动读取公开仓库 `_posts/` 下所有符合 Jekyll 日期命名的 Markdown 文章，包括嵌套目录、未来日期和 `published: false` 的文件。无需先授权；私有仓库需连接后才能读取。列表按日期从新到旧排列，显示文章标题，可搜索标题、日期、短名和已读取的正文。标题与正文逐步加载，搜索结果会随读取完成更新；点 **刷新** 检查远端更新。

点击文章即可编辑并保存本机草稿，连接 GitHub 后才能提交。再次打开同一远端版本时会恢复最新的关联草稿，保留尚未提交的修改，避免重复创建草稿。远端版本已更新时会另开新草稿，原草稿仍在本机列表中，防止覆盖未提交的内容。GitHub 对匿名读取有更低的请求限额，达到限额时可连接 GitHub 后继续读取。

本地文件和 Pages 上的写作室都可以发起连接。连接时需要能访问 GitHub；若浏览器限制本地页面请求，可在已部署的 `/admin/` 页面操作。

## 直接发布、修改和删除

| 操作 | 做法 |
| --- | --- |
| 发布新文章 | 点 **＋** 写作，然后点 **发布到博客**。即使 `_posts/` 被删空，发布时也会自动创建目录。 |
| 修改线上文章 | 从左侧 **全部文章** 搜索并打开文章，修改后点 **更新线上文章**。保存本机草稿不会更新线上文章。 |
| 删除线上文章 | 先打开该文章，点 **删除线上文章**，核对标题和文件名后再次确认。本机草稿和图片会保留。 |
| 查看是否上线 | 提交完成后点 **查看部署进度**，等待 GitHub Pages 成功，再打开博客确认。 |

文章和本次新增图片会合并为一次提交。修改线上文章时保留原文件名；改标题不会创建重复文章。提交前会检查读取时的文件版本，如果别人已改过这篇文章，或者提交期间分支发生变化，会停止操作，避免覆盖。遇到此提示，先导出当前草稿，再刷新并重新打开线上版本核对。

若远端已有同名但内容不同的图片，发布会停止；重新插入图片以生成新文件名，或调整文件名后再试。删除文章不会顺便删除图片，以免影响其他文章。

**提交成功只代表 GitHub 已接收修改，网站还需等待 Pages 构建和部署。** 原文章的 `published: false` 会被保留，因此该文章仍不公开展示。当前没有定时发布，日期需为今天或更早。若提示提交结果待确认，先查看 GitHub 提交记录，不要连续重复发布；导出备份后重新读取线上文章。

## 打开已有文章与插图

- “打开文章”支持 `.md`、`.markdown`，以及本编辑器导出的**单篇文章 ZIP**。整站压缩包不属于此入口的导入范围。
- 导入已有 Jekyll 文章时保留合法原文件名，避免改标题后重复发布；已有日期的时间部分在日期未修改时保留。
- 点击“图片”选择 PNG、JPG、WebP 或 GIF，也可粘贴、拖入图片；每张不超过 8 MB。图片随草稿保存，导出时一起打包。
- 只打开一个 Markdown 文件不会自动带入它旁边的图片。继续编辑带图片的文章，优先打开此前导出的 ZIP。

## 导出备份与手动发布

不连接 GitHub 时也能使用 **导出备份**：

| 文章情况 | 下载结果 | 放到哪里 |
| --- | --- | --- |
| 没有需要打包的图片 | `YYYY-MM-DD-短名.md` | 仓库的 `_posts/` |
| 含编辑器保存且正文正在使用的图片 | 单篇文章 ZIP | 解压后把 `_posts/`、`assets/` 内文件放入仓库同名目录 |

导出只下载文件，不会发布。需要手动上传时，先解压 ZIP，将文章和图片放到仓库的对应目录，再提交并等待 Pages 完成部署。不要把 ZIP 本身当作文章上传。编辑器只允许导出今天或更早日期的文章。

## 可视化与原文模式

普通 Markdown 使用可视化编辑，例如段落、标题、加粗、斜体、列表、引用、链接、图片和代码块。

识别到 Liquid 模板、HTML、表格等高级内容时，编辑器会进入“原文模式”，保留这些语法，并允许直接修改原文。仍含高级格式时，不能切回可视化模式，以免转换丢失内容。文章开头的其他 YAML 元数据随文件保存，YAML 的排版和注释不会原样保留。

右侧预览共用博客的 `assets/css/style.css` 和 `typography.css`，但只渲染 Markdown，不执行 Liquid 或 Jekyll 构建。模板指令、特殊语法、代码高亮等效果应以正式网站为准；手机按钮只模拟较窄的阅读区域。

## 使用边界

浏览器草稿不会自动同步到 GitHub；只有点击发布、更新或确认删除，才会提交对应操作。另一台设备可以连接 GitHub 读取已提交文章，但读不到这台设备尚未发布的草稿。

把 `/admin/` 放到公开网站，不会让访问者获得你的仓库权限。每个访问者需要提供自己拥有权限的授权码。仓库分支若禁止直接提交，此版本会提示失败，不会绕过保护规则。

## 文件职责与重建

| 文件 | 职责 |
| --- | --- |
| `index.html`、`editor.css` | 写作界面与界面样式 |
| `app.js` | 编辑器初始化、按钮、导入导出及图片管理 |
| `modules/article-files.js` | YAML 元数据解析、日期与文件名校验、文章文件生成；正文保持独立 |
| `modules/draft-store.js` | IndexedDB 草稿与图片存储 |
| `modules/preview.js` | 清理预览内容、加载博客 CSS、更新阅读预览 |
| `modules/github-client.js` | GitHub 请求、文件版本检查、文章和图片的单次提交 |
| `modules/github-panel.js` | 连接窗口、线上文章列表、读取、发布和删除操作 |
| `vendor/` | 已打包的第三方库及许可证说明 |
| `build/` | 依赖清单、锁文件、第三方库打包入口与脚本 |

富文本编辑使用固定版本 **Tiptap 3.32.0**；其 Markdown 扩展仍处于 beta，因此复杂内容采用原文保护。`js-yaml` 使用 `CORE_SCHEMA` 处理文章头部，`DOMPurify` 清理粘贴及预览 HTML，`fflate` 读写文章 ZIP，`marked` 渲染预览。

只有升级或重新打包依赖时，才需要安装 Node，在 `admin/build/` 目录运行：

```sh
npm ci
npm run build
```

构建会更新 `admin/vendor/editor-vendor.js`、`THIRD_PARTY.md` 及完整许可证文件。通常修改界面、文件模块或博客样式，无需重建第三方依赖。

Jekyll 配置仅排除 `admin/build` 和 `admin/README.md`，写作室运行文件可作为静态页面发布。根目录 `.gitignore` 使用 `/vendor/`，只忽略 Ruby 依赖，不会漏掉 `admin/vendor/`。
